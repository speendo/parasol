# 0.10 Message Follow-ups Design

**Status:** proposed, awaiting approval (2026-11-15). Target: 0.10.0.
**Parent:** `2026-11-13-prsl-message-design.md`, `2026-11-13-0.10-scope-design.md`.
**Branch:** `feature/0.10-message-followups`.

## Why

The first `prsl_message` implementation merged on 2026-11-15. Review and
the branch owner found follow-up work that belongs in 0.10.0 before the
release tag:

- a save could erase a message that arrived while the save was pending
  (already fixed on `main`: `syncThen()` no longer clears the status bar),
- a partial outbound frame could render `undefined`,
- a test-only export shipped in the production bundle,
- status text was not announced to screen readers and could not be
  dismissed,
- message size was unbounded on a device with limited heap,
- the WebSocket had two ways to show a red line: `type:"error"` for
  protocol failures and `type:"message", level:"error"` for application
  errors.

The branch owner decided to unify the wire and harden the message path
before 0.10.0, while the wire is still allowed to change.

## Goals

- One WebSocket path for user-visible red text.
- Bound the device-side message size before it allocates.
- Never render `undefined` from a malformed frame.
- Announce status text and let the user dismiss it.
- Remove production code that exists only for tests.
- Set `library.json` to `0.10.0` and record the release in `CHANGELOG.md`.

## Non-goals

- Auto-dismiss or message history.
- Per-client targeting or message access control.
- A full README / API reference / presentation pass.
- Creating the `v0.10.0` tag. The tag waits for the remaining release
  gates (real-hardware verification, docs pass).
- Client-side JSON parse hardening (see Decisions).

## Decisions

### 1. One wire path: `type:"message"` replaces `type:"error"`

The device sends exactly four protocol failures today, all to the sender
only: invalid JSON, missing/non-numeric apply `i`, invalid `data`, and
missing sync `i`. They become:

```json
{"type":"message","level":"error","message":"Missing apply id"}
```

The client drops its `type:"error"` branch; `type:"message"` already
renders ERROR with the `\u2716` glyph and red color. `showError()` stays
for local, non-wire failures (HTTP request failures, rejected fields).

This is a breaking wire change. Pre-1.0 rules make it a minor bump:
`0.10.0`.

### 2. Message length cap: reject above 512 bytes

`include/prsl.h` gains:

```c
#define PRSL_MSG_MAX 512   /* max bytes accepted by prsl_message() */
```

`prsl_message()` checks `strlen(message) > PRSL_MSG_MAX` before creating
any cJSON and returns `ESP_ERR_INVALID_ARG`. The header documents the
limit as bytes. Rejection is chosen over truncation: it costs one
comparison, cannot split a UTF-8 sequence, and never allocates for an
oversized message.

`PRSL_MSG_MAX` is a ceiling on the caller's text, not a reserved buffer.
Nothing allocates 512 bytes up front: a 20-byte message costs roughly
150 bytes transient, and a 512-byte message costs roughly 3 KB. The
memory is freed as soon as the shared send buffer drains.

Why 512: the transient cost is one cJSON node plus the printed JSON plus
one shared `textAll` buffer, about 3 KB worst case with escaping. That is
irrelevant next to the ESP32's heap; the real limit is the footer, where
512 bytes is already several lines. 160 was over-cautious.

### 3. No partial frames

`prsl_message()` checks all three `cJSON_AddStringToObject()` results. If
any fails it deletes the root object and returns `ESP_ERR_NO_MEM`. The
header already promises that return.

### 4. Client defaults missing text to an empty string

`showMessage()` uses `icon + ' ' + (msg || '')`. A frame without a
`message` key renders `\u2139 ` rather than `\u2139 undefined`. No other
coercion defense is added: only this library emits the frame, and
`textContent` already prevents markup injection.

### 5. Screen-reader announcement

`#status-bar` gets `role="status"` in `index.html`. This is a polite live
region: the browser announces text changes without stealing focus. No
JavaScript cost. Errors and application messages share the region.

### 6. Dismiss button

A real button sits next to the status bar:

```html
<button id="status-dismiss" type="button" aria-label="Dismiss message" hidden>&times;</button>
```

- `showError()` and `showMessage()` set `statusDismiss.hidden = false`.
- `clearStatus()` sets it back to `true`.
- A click listener on the button calls `clearStatus()`.
- It applies to every status-bar line: messages, protocol errors, HTTP
  failures, and rejected-field notices.
- Initial `hidden` keeps the existing footer-visibility rule working.

Sketch:

```
[ ⚠ Wi-Fi changed; reconnect   × ]        [Reset] [Save]
```

### 7. Drop the test-only export

`showMessage` leaves the returned `parasol` object. Unit tests drive the
real path with `window.__test.receiveWSMessage({ data: JSON.stringify({
type: 'message', ... }) })`, which is already dev-only. No `__test` hook
is added for `showMessage`. This removes the symbol from the production
bundle.

### 8. Version and changelog

- `library.json`: `"version": "0.10.0"`.
- `CHANGELOG.md`: a `## 0.10.0` section covering the correctness fixes,
  `prsl_message`, the unified error wire, the cap, the dismiss button,
  aria, and the measured JS budget.
- `WS_PROTOCOL.md`: the `type:"error"` section becomes the
  `type:"message"` ERROR level; every protocol-error reference updates.
- `API_REFERENCE.md`: add the missing `prsl_message` entry and the
  512-byte limit. The rest of the docs pass stays deferred.
- One release: 0.10.0 contains the correctness fixes, the message API,
  and these follow-ups. The project's table makes `0.10.1` a patch slot,
  so a feature or a breaking wire change cannot ship there; the
  alternative would be 0.11.0, which needs a side `release/0.10.0`
  branch. The branch owner chose one 0.10.0.
- No tag in this branch.

### 9. Malformed inbound JSON stays as-is

The device already answers invalid client JSON with a protocol error
(now a message frame). The browser's `JSON.parse` throws to the console
and the socket stays open; this only happens with buggy firmware, and a
try/catch would spend bytes hiding a firmware bug. No change.

### 10. Rename `clearError()` to `clearStatus()`

The function clears every status-bar line: INFO/WARNING/ERROR messages,
protocol errors, HTTP request failures, and rejected-field notices.
`clearError` no longer names what it does; `clearMessage` would imply it
only clears messages. `clearStatus` matches the element it clears and
has no public documentation to update — only `app.js` and its tests use
it.

## Approaches and why the chosen one

**Wire.** Unify now (chosen) vs keep `type:"error"` as a protocol path vs
accept both for one release. Keeping both is the exact confusion the
branch owner rejected; accepting both keeps the duplicate client branch
and defers no risk, because client and assets ship from the same device.

**Cap.** Reject over 512 bytes (chosen) vs truncate vs no cap. Truncation
needs UTF-8 boundary handling and still allocates; no cap leaves heap use
to the caller. Rejection is the smallest safe guard, and 512 keeps the
worst-case transient well under 3 KB.

**Dismiss.** Separate button (chosen) vs making the status bar itself
clickable vs CSS-only affordance. A real button is keyboard- and
screen-reader-accessible and does not overload the `<mark>`.

**Test access.** Drive the WebSocket handler (chosen) vs keep the export
vs add a dev-only `__test` hook. Driving the handler tests more of the
real path and ships nothing.

## Constraints

- ESP32: no new allocation in a failure path; cap before cJSON.
- Client: `app.min.js` should not grow materially; measure and record
  gzip. The export removal and error-branch removal are expected to
  offset the dismiss additions. Target ≤ +30 gzip over 7,981.
- Generated assets (`app.min.js`, `src/prsl_assets.c/h`) are rebuilt and
  committed with the source.
- `type:"error"` disappears from the library sources; it may still appear
  in historical specs and CHANGELOG entries for 0.9.
- Do not rewrite the already-merged commits. A follow-up branch carries
  these changes and the release commit.

## Acceptance criteria

- `grep -rn '"type":"error"' src/` returns nothing.
- Native `ws_handle` tests assert `type:"message"`, `level:"error"`, and
  the message text for the protocol failures.
- Unit tests: no direct `window.showMessage` calls; every message test
  goes through `receiveWSMessage`. Missing text renders `\u2139 `,
  markup stays literal (`<img onerror>` creates no element), a message
  mid-batch leaves in-flight/baseline state untouched, and a message
  during a save survives.
- E2E: `#status-bar` has `role="status"`; a message shows the dismiss
  button, clicking it clears text and color; a message sent after a
  settings push does not block the form.
- `prsl_message` rejects 513 bytes and accepts 512 (compile-only on the
  device; the constant and check are reviewed and documented).
- `clearError` no longer appears in `app.js` or `tests/unit/app.test.js`;
  `clearStatus` does.
- `library.json` is `0.10.0`; `CHANGELOG.md` has the 0.10.0 section;
  `WS_PROTOCOL.md` and the `prsl_message` API entry match the wire.
- Full suite green: `npm test`, `pytest test_server -q`,
  `pio run -d tests/pio_smoke`, committed assets in sync.
- No `v0.10.0` tag.
