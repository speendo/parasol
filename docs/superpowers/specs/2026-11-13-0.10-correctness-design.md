# 0.10 Correctness Implementation Spec

**Parent:** `2026-11-13-0.10-scope-design.md`
**Branch:** `feature/0.10-correctness`
**Goal:** Close the three real correctness gaps and add two cheap tests.

## Scope

1. Initialize the save-handler error path.
2. Bound sync recovery when a reply omits a key.
3. Define and enforce the `prsl_stop()` shutdown contract.
4. Add a reconnect-while-dirty e2e test.
5. Add a busy-state failure-clearing unit test.

Non-goals: an in-flight request barrier, multi-client conflict resolution,
per-endpoint state, or any wire change.

## 1. Save-handler `err` initialization

### Problem

In `src/prsl.cpp`, the save handler declares `char err[128];` and only fills
it when `prsl_apply_save_body()` returns a status. On the `buf == NULL`
fallback it calls `req->send(400, "text/plain", err)` with an uninitialized
buffer.

The path is reachable under memory pressure: the first chunk's `malloc`
fails, later chunks still arrive, and the final chunk reaches the fallback
with `_tempObject == NULL`.

### Required behavior

- If `buf == NULL`, respond `500` with `"Out of memory"` and do not call
  `prsl_apply_save_body()`.
- Keep `err` initialized to a safe fallback regardless, so no future branch
  can send uninitialized bytes.
- Release the store mutex before sending the response.

### Acceptance

- A native or host test can exercise the `buf == NULL` decision if the path
  is factored into a small helper; otherwise the behavior is verified by
  inspection and the existing save tests stay green.
- `npm test` passes.

## 2. Bound sync recovery

### Problem

`app.js` feeds every authoritative value into recovery. When a sync reply
omits a key the client is recovering, `resolveRecovering()` never runs for
that key, and `maybeSync()` immediately sends another sync. A malformed or
partial server can keep the client in a request/reply loop.

### Required behavior

In the recovery loop, if the key is absent from the payload:

```js
if (rv === undefined) { if (isReply) delete recovering[rk]; continue; }
```

- Only drop the key on a **sync reply**, not on an ordinary push.
- Dropping means “terminal, stop waiting,” matching the sync-timeout outcome.
- Do not resend the value again after dropping it.

Measured client cost: +14 raw / +11 gzip bytes with the project's terser
settings.

### Acceptance

- Unit test: put a key in `recovering`, deliver a sync reply that omits it,
  assert exactly one sync was sent and `recovering` is empty afterward.
- Existing sync/recovery tests remain green.
- No change to the wire format.

## 3. `prsl_stop()` contract and stopping guard

### Contract wording

Use this wording in `include/prsl.h` and the API reference:

> `prsl_stop()` is a shutdown call, not a reboot step.
>
> Call it from your main task (`setup()`/`loop()`) at a quiet moment, when
> the web UI is not in the middle of a request.
>
> Never call it from `on_save`, `on_reset`, `on_reboot`, or `on_upload`.
> Those callbacks run inside a request; `prsl_stop()` frees state that the
> request still needs.
>
> Rebooting does not need it. Do pre-reboot cleanup in `on_reboot`, then
> call `esp_restart()`.
>
> If you need an orderly shutdown before a reboot, set a flag in `on_reboot`
> and return; call `prsl_stop()` and `esp_restart()` from the main loop.

Add a short safe/unsafe table to the API reference:

| Where you call it | Safe? |
|---|---|
| `setup()` before starting the UI | Yes |
| `loop()` just before `esp_restart()` | Yes |
| `loop()` while a browser is actively saving | No |
| Inside `on_save` / `on_reset` / `on_reboot` / `on_upload` | No |
| From an interrupt or an unrelated FreeRTOS task | No |

### Stopping guard

- Add a `g_stopping` flag set at the start of `prsl_stop()`.
- Every HTTP handler entry checks it and returns `503` with
  `"Stopping"` instead of touching the store or callbacks.
- Body callbacks also bail out without buffering when stopping.
- Clear the flag in `prsl_init()` so a fresh lifecycle can start.
- Keep the existing upload abort and mutex behavior unchanged.

This reduces the race but does not replace the contract: the developer still
stops at a quiet moment. No in-flight counter, no barrier, no wait loop.

### Acceptance

- A host test covers the stopping predicate if the handler checks are
  factored into a small helper; otherwise the hardware check covers
  `prsl_stop()` mid-upload and mid-save.
- The header and API reference contain the contract wording and table.
- `prsl_stop()` remains safe to call twice? If not already, document the
  second call returning `ESP_ERR_INVALID_STATE`.

## 4. Reconnect-while-dirty e2e test

Scenario:

1. Load the page.
2. Change a field so the form is dirty but do not Save.
3. Drop the WebSocket.
4. Reconnect.
5. Assert the edited value survives and is re-sent; untouched fields are not
   spuriously resent.

Use the existing Playwright helpers. Add to `tests/e2e/app.test.js` or a
small new file. If the test exposes a real bug, fix it in this branch; if it
only confirms current behavior, keep the test.

## 5. Busy-state failure test

Extend the Save tests:

- Make `fetch` reject or return a non-OK response.
- Click Save.
- Assert `aria-busy` is removed from the Save button.
- Assert the error is shown.

The implementation already removes `aria-busy` in `.then()` regardless of
`ok`; this test pins it.

## Files likely touched

- `src/prsl.cpp` — save error path, stopping flag, handler checks.
- `src/prsl_upload.c` / `src/prsl.cpp` — stopping guard in upload handlers.
- `include/prsl.h` — `prsl_stop()` contract words.
- `API_REFERENCE.md` — contract table (docs pass may move it; keep the header
  wording now).
- `app.js` — sync recovery guard.
- `tests/unit/app.test.js` — sync guard and busy-state failure tests.
- `tests/e2e/app.test.js` — reconnect-dirty test.

## Risks

- The stopping guard may reject a request that was already in flight before
  `prsl_stop()`; that is the intended behavior, but document the `503`.
- The sync guard must not drop a key on an ordinary partial push; only on a
  reply tagged with the sync id.
- Do not expand this branch into a full teardown barrier.
