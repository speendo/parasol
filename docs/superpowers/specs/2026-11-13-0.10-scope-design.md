# Parasol 0.10 Scope and Branch Plan

**Status:** decided in brainstorming, 2026-11-13. Branch order revised
2026-11-14.
**Target:** 0.10.0.
**Sources:** `docs/BACKLOG.md`, the 0.9 ack-correlation spec, and the
2026-11-13 code-item review.

## Why this spec exists

Parasol is a settings UI for one ESP32 on a local network. It is not a
general-purpose device-management framework. The backlog had accumulated
speculative work — protocol versions, per-field timeouts, ticket memory,
field-level roles, multi-client conflict resolution — that does not match
that deployment model.

This spec freezes the 0.10 code surface. Documentation and presentation work
is deliberately postponed until the code is feature-complete.

## Goals

- Fix the small number of real correctness problems.
- Add one general, cheap way for firmware to show a user-facing message.
- Provide a complete application-level cookie lock as an example, without
  putting authentication policy into the library.
- Leave the device stateless and the wire small.
- Define what is deferred to later work and what is out of scope.

## Non-goals

- Library-owned users, passwords, sessions, roles, or login UI.
- Field-level access control.
- Multiple independent endpoints in 0.10.
- Multi-client conflict resolution or operational transforms.
- Server-side message/ticket history.
- Device-wide settings versions.
- Per-field timeouts.
- A general file manager, download manager, mDNS browser, or graphing tool.

## Anti-goals

- A security feature that only disables a browser control while the raw
  endpoint stays open.
- A new public API whose only justification is a hypothetical deployment.
- A 0.10 release that silently changes the 0.9 wire contract.

## Deployment model

The design assumes:

- one ESP32,
- one settings store,
- usually one browser tab,
- a trusted LAN,
- infrequent settings changes,
- `on_set` callbacks that are fast and idempotent.

Deployments outside that model must add their own transport security,
authentication, and conflict policy.

## Branch plan

Each branch starts from `main` after this spec and the backlog update land,
and carries its own sub-spec. Plans are local working documents at
`docs/superpowers/plans/2026-11-14-<name>.md`; that directory is gitignored, so
plans are not committed. No branch implements more than one independent
concern: three code branches, three plans, merged one at a time.

Work lands in this order:

| # | Branch | Sub-spec | Work |
|---|---|---|---|
| 0 | `docs/future-endpoints-actions` | `2026-11-13-endpoints-actions-design.md` | Design-only roadmap; **merged 2026-11-14**, no plan |
| 1 | `feature/0.10-correctness` | `2026-11-13-0.10-correctness-design.md` | Save `err` init; sync recovery guard; `prsl_stop()` contract and stopping guard; reconnect-dirty e2e test; busy-state failure test if cheap |
| 2 | `feature/0.10-message-api` | `2026-11-13-prsl-message-design.md` | `prsl_message()` enum, API, wire message, client rendering and symbols, tests |
| 3 | `feature/0.10-secure-example` | `2026-11-13-secure-example-design.md` | `examples/secure`: login/logout, cookie session, HTTP + WS gate, CI compile check |

Why this order:

- The docs branch is design-only, so it lands first and leaves no plan. It
  also resolves the backlog link to its spec.
- Correctness is the shortest path to a shippable baseline and adds no public
  API. Its client changes settle the `onWSMessage` path that the message plan
  extends.
- Message follows correctness because both edit `app.js`,
  `tests/unit/app.test.js`, and the generated `src/prsl_assets.c`. Branching
  message from an updated `main` means one clean second asset regeneration
  instead of a hand-merge inside the generated gzip byte array.
- The secure example touches no library source, `app.js`, or assets, so it may
  run in parallel with correctness. Merging it last keeps it reviewed against
  a settled library and leaves no rebase.

The scope docs land on `main` first, so every feature branch is based on the
same `main` plus the scope spec and backlog. Each plan is written on its own
branch after the preceding branch has merged, so it refers to current line
numbers.

## 0.10 code scope

### Correctness

Three small changes:

1. Initialize the save handler's error buffer on the `buf == NULL` path.
2. When a sync reply omits a key the client is recovering, drop that key
   instead of re-arming another sync. This costs about +11 gzip bytes.
3. Define and enforce the `prsl_stop()` contract:

   - `prsl_stop()` is a shutdown call, not a reboot step.
   - Call it from the main task (`setup()`/`loop()`) at a quiet moment.
   - Never call it from `on_save`, `on_reset`, `on_reboot`, or `on_upload`.
   - A reboot does not need it: `on_reboot` does pre-reboot cleanup, then
     `esp_restart()`.
   - A stopping flag rejects new work once teardown begins.

The full wording, test, and acceptance criteria are in the correctness
sub-spec.

### User messages

Add one public function:

```c
typedef enum {
    PRSL_MSG_INFO,
    PRSL_MSG_WARNING,
    PRSL_MSG_ERROR
} prsl_msg_level_t;

esp_err_t prsl_message(prsl_msg_level_t level, const char *message);
```

It broadcasts to every connected browser:

```json
{"type":"message","level":"warning","message":"Wi-Fi changed; reconnect"}
```

The browser prefixes INFO with `ℹ`, WARNING with `⚠`, and ERROR with `✖`,
and colors WARNING amber and ERROR red. The library does not store the
message; it is transient UI feedback. Protocol failures keep using the
existing `type:"error"` path.

Full API, wire, client, and test details are in the message sub-spec.

### Security

0.10 does **not** add an auth API to the library. It ships a complete
application-level example:

- login/logout routes,
- a single shared password (example value; replaceable),
- a random in-RAM session token,
- `HttpOnly; SameSite=Strict` cookie (`Secure` when HTTPS is used),
- server-wide middleware that gates the page, static assets, API, and the
  WebSocket handshake,
- an `Origin` check for WebSocket upgrades,
- documentation that plain HTTP makes both cookies and Basic credentials
  sniffable, so the example is for a trusted LAN or a TLS-terminating setup.

The example is compile-checked in CI. Full design is in the secure-example
sub-spec.

## Deferred (not scheduled)

### Independent endpoints

`/user` and `/admin` must be independent, not filtered views of one global
store. That means:

- per-endpoint store, dirty flag, callbacks, WebSocket, and upload state;
- endpoint-scoped runtime API;
- per-endpoint auth at the boundary;
- base-path-aware assets and client URLs.

This is the “two separate rooms” model. The cheaper “same room, filtered
view” model was rejected because shared dirty state, callbacks, upload lock,
and group IDs leak immediately.

### `prsl_add_action`

One-shot actions (factory reset, calibrate, format) should be actions, not
settings fields. The API is deferred until a concrete need exists. It should
carry its own confirmation semantics.

The endpoint/action design is recorded in the future-work sub-spec. It is
not a 0.10 commitment.

## Out of scope / application-level

These are not library roadmap items. They may be examples or application
features later:

- export/import settings (buildable from existing save/upload),
- file download,
- file-size display,
- optional upload confirmation,
- mDNS discovery,
- status history/graphs,
- accordion merge of settings and status,
- additional nav actions beyond reboot.

Also dropped as library features because firmware can already handle them:

- upload chunk-size alignment (buffer in `on_upload`),
- custom filename regex (use `accept` plus content checks),
- structured file metadata (encode size/checksum in the file label).

## Release gates after the code is complete

These are tracked in the backlog, not implemented by the feature branches:

- real-hardware verification (OTA, LittleFS/SD writes, disconnect → `ABORT`,
  idle timeout, `prsl_stop()` mid-upload, real save/reset),
- README, `API_REFERENCE.md`, `WS_PROTOCOL.md`, field-format upload matrix,
  CHANGELOG, examples, tags,
- semver/deprecation/stability promise,
- PlatformIO Registry publication and Arduino IDE limitation note.

## Acceptance criteria for 0.10

- `npm test` is green on `main` after each branch merges.
- No new public API except `prsl_message` and the `prsl_stop` contract words.
- The sync recovery loop is bounded.
- `examples/secure` compiles and gates HTTP and WS.
- The backlog reflects the dropped/deferred decisions.
- `library.json` is 0.10.0 and the tag matches.
